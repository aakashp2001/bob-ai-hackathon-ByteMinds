# Model Context Protocol (MCP) Documentation

## Overview
The `missing-person-case` MCP server provides a standardized interface for AI models to interact with fictional missing person case data. It exposes a set of tools that allow for deep dive analysis into case profiles, investigator tips, CCTV sightings, and backend correlation results.

## Configuration
The server is built using the Model Context Protocol SDK and uses `stdio` as the transport layer.

- **Server Name:** `missing-person-case`
- **Version:** `1.0.0`
- **Runtime:** Node.js (ES Modules)

## Getting Started

### Prerequisites
- Node.js 18 or higher.
- `@modelcontextprotocol/sdk` and `zod` installed (see `package.json`).

### Running the Server
To start the MCP server locally:
```bash
npm start
```
The server will start and wait for JSON-RPC messages over standard input.

## Tools Reference

The following tools are registered and available for use by an MCP client:

### `get_person_profile`
Retrieves the family-provided missing-person profile.
- **Input:** `caseNumber` (string) - Fictional missing-person case number.
- **Returns:** Object containing personal details (name, age, physical description, last seen info, etc.).

### `get_investigator_tips`
Retrieves all mock investigator tips without modifying or scoring them.
- **Input:** `caseNumber` (string) - Fictional missing-person case number.
- **Returns:** Object containing an array of tips with source information and timestamps.

### `get_cctv_sightings`
Retrieves mock CCTV descriptions and preserves source IDs.
- **Input:** `caseNumber` (string) - Fictional missing-person case number.
- **Returns:** Object containing descriptions of sightings captured on CCTV.

### `get_case_data`
Retrieves the full case context from the backend contract. This is a convenience tool that aggregates profile, tips, and sightings.
- **Input:** `caseNumber` (string) - Fictional missing-person case number.
- **Returns:** A complete snapshot of the case record.

### `get_correlation_results`
Retrieves backend correlation results without recalculating scores. These results are typically generated by an analysis pipeline.
- **Input:** `caseNumber` (string) - Fictional missing-person case number.
- **Returns:** Analysis results including potential leads and their confidence scores.

## Backend Implementation

The MCP server acts as a bridge to a mock backend client defined in `src/mcp/backendClient.js`.

- **Data Source:** `src/integration/mockCaseData.json`
- **Normalization:** Case numbers are automatically trimmed and converted to uppercase.
- **Error Handling:** The backend client maps internal errors to MCP-compatible error responses.

### Error Codes
| Code | Description |
|---|---|
| `CASE_NOT_FOUND` | The provided case number does not exist in the dataset. |
| `BACKEND_UNAVAILABLE` | The data source could not be reached. |
| `INVALID_BACKEND_RESPONSE` | The data source returned unexpected or malformed data. |
| `CORRELATION_UNAVAILABLE` | Analysis results have not been generated for this case yet. |

## Development and Testing

### Testing
Tests for the backend client and MCP logic are located in `tests/mcp/`.
To run tests:
```bash
npm test
```

### Extending the Server
To add a new tool:
1. Define the logic in `src/mcp/backendClient.js`.
2. Register the tool in `src/mcp/server.js` using `server.registerTool`.
3. Define the input schema using `zod`.
